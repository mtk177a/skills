# エージェント向けの指示を設計する

意図するクライアントに、明確な権限と少ない重複で届く、最小の指示文書の集まりを設計する。\
各文書の役割は、確かめたクライアントでの扱いと、リポジトリの必要に基づいて決める。\
出力は設計であり、指示のファイルは変更しない。

## 作業手順

1. **目標を定める**

   意図する挙動、範囲、実際に使っている利用者、クライアント、モデル、共通にするものとクライアント固有にするものを定める。\
   依頼が原因の分からない挙動から始まっていて、現在の指示の読み込みや権限が不確かな場合は、止まる。\
   先に診断が必要であることを報告し、足りない証拠を示す。

2. **現在の文書の集まりを調べる**

   既存の指示文書、クライアントの設定、インポート、規則、フック、方針の置き場所、プロジェクトの文書を調べる。\
   観測した読み込みの証拠、トレース、訂正、失敗と、ローカルの方針と許可の範囲を集める。\
   観測した証拠、推論、前提、不明点を分ける。\
   標準のファイル名のファイルがないことは、実際に使っているクライアントの必要に照らして評価する。

3. **クライアントでの扱いを確かめる**

   対象のクライアントごとに、読み込み、発見、優先順位、インポート、強制の扱いを確かめて記録する。\
   クライアントの現在の公式の文書を使う。\
   あるクライアントの階層は、ほかのクライアントと異なることがあるので、クライアントごとに分けて記録する。\
   指示文書は、挙動を導く文脈として扱う。\
   強制として扱うのは、現在のクライアントでの扱いがそう定めている場合だけにする。

4. **基準となる場所を選ぶ**

   共通の事実や規則ごとに、基準となる場所を一つ選ぶ。\
   インポート、参照、生成した表示は、対象のクライアントがそれに対応していて、権限を隠さずに食い違いを減らせる場合だけ使う。

5. **指示と強制を分ける**

   継続して参照する挙動の指示を、強制される許可設定や、処理の自動実行と分ける。\
   保証が必要で、クライアントが方針、設定、フックを提供している場合は、保証をそこに置く。

6. **常に読み込まれるファイルの内容を決める**

   クライアントが毎回のセッションで読み込むファイルは、毎回のセッションでコンテキストを消費する。\
   そこには、次の 2 つの条件を満たす内容だけを入れる。

   - エージェントが、ほとんどの作業でそれを必要とする。
   - エージェントが、それを自分で手軽に見つけられない。\
     たとえば、書かれていない慣例、選択の理由、強い防護柵である。

   コマンド、ディレクトリの構成、設定のように、エージェントが調べられる事実は、その場所を示す。\
   そのような事実を写すのは、調べるのに手間がかかる場合だけにする。\
   内容は肯定の形の指示で書き、禁止は強い防護柵にだけ使い、望む行動と組にする。\
   ある種類の作業のための指示は、その作業のときにエージェントが読む文書に置く。

7. **文書を決める**

   必要な文書と、設定の置き場所を決める。\
   クライアント固有の補助ファイルは、そのクライアントを実際に使っていて、基準となる場所を直接読めない場合だけ加える。\
   各置き場所に何を置き、何をほかの置き場所に任せるかを定める。\
   プロジェクトの一般的な事実は、エージェントの文脈にある必要がない限り、通常の文書に置く。\
   秘密情報、認証情報、個人情報、非公開の運用データは、テンプレートや例に入れない。

8. **文書の集まりを確かめる**

   重複、食い違い、コンテキストの消費、移植性、担当、更新の経路を確かめる。\
   当てはまる場合は、コンテキストの圧縮や遅延読み込みの後の挙動も確かめる。\
   提案する集まりを、3 つの代案と比べる: 現在の集まり、重複する指示を除いた現在の集まり、より小さな橋渡しの文書。

9. **確かめ方を計画する**

   重要なリスクから、確かめ方を定める。

   - 各クライアントが、意図した文書を読み込むか
   - 優先順位の食い違い
   - 指示の順守
   - 強制の範囲
   - 実際に使っているクライアントどうしの共存

10. **引き継ぎを用意する**

    範囲を定めた、実装への引き継ぎを用意する。\
    ファイルの変更は、許可された実装の作業手順が行う。

## 報告

判断に合った構成で、次の項目を含める。

- 推奨する文書の集まりと、それが代案より良い理由
- 意図する挙動、範囲、実際に使っているクライアント、未解決の前提
- クライアントごとに確かめた、読み込み、発見、優先順位、インポート、強制の扱い
- 基準となる場所と、各置き場所の責務
- 常に読み込まれる各ファイルの内容と、それ以外の内容の置き場所
- 設計に含めない文書や置き場所と、その理由
- 重複、コンテキストの消費、移植性、保守、移行のリスク
- 確かめ方と、実装の変更の単位
- 未解決の挙動のために健全な設計ができない場合は、足りない証拠を示した診断への引き継ぎ

補助の文書、決まったファイル名、決まった見出しのテンプレートは、クライアントやリポジトリが必要とする場合だけ加える。\
挙動が確かめられていない場合は、必要な診断の証拠を示し、設計を仮説として示す。
