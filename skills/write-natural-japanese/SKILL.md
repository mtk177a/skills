# 自然な日本語を書く

日本語の文章が主要な成果物なら、新規執筆、翻訳、リライト、推敲を依頼の範囲で完成させる。読者が内容と文同士の関係を理解できるよう、必要な構成、短い説明、語彙、構文を整える。AI らしさの検出や禁止語の置換を目的にしない。

## 入力の役割と変更範囲を捉える

依頼と参照できる文脈から、目的、読者、媒体、読後に理解・判断・操作してほしいことを捉える。ユーザーの明示指定、引用、対象文書の規約、既存の文体・用語を優先する。読者が通常参照する返信先のメール、既存スレッド、直前の節は文脈として使えるが、読者に見えない執筆用の会話だけに依存する指示語を完成稿に残さない。

入力を見た目で原稿かメモかに決めず、何を忠実に保ち、何を執筆材料として選べるか、要約・削除・再構成まで任されているかを判断する。指定がなければ「読者には不要そう」という理由だけで原稿の主張を削らない。毎回の確認を入口条件にせず、変更幅が不明で意味が変わる箇所だけを確認する。

- **忠実な翻訳・推敲**では、主張、主体と対象、条件、否定・修飾の範囲、確度、帰属、依頼・許可・義務などの発話意図を守る。語順、文の分割、主語の明示・省略、丁寧さは調整できる。翻訳は原文の全事実を独立に調査する依頼ではない。未検証というだけで止めたり主張を直したりせず、訳せる曖昧さは保つ。不可欠な選択だけを確認し、誤りの疑いを示すなら訳文と分ける。
- **材料からの新規執筆、要約・再構成を任された改稿**では、読者に必要で、渡してよい情報を選ぶ。執筆指示、訂正の経緯、内部作業名は、読者に必要な内容でなければ持ち込まない。指定された全項目は伝え、要約しても結論を支える条件や留保は残す。読者に必要でも開示できない情報は、言い換えるだけで掲載可能にはならない。

複数の関連文書が同じ依頼に含まれる場合だけ、共有する意味と用語をそろえる。同じ依頼に含まれない文書へ作業を広げない。

## 任された完成稿を書く

入力が支える関係の明示、情報の並べ替え、短い語義説明を行い、依頼された読者が使える文章にする。一般的な語義と製品・案件固有の仕様を分け、新しい事実、原因、判断理由、要件、約束、期限を作らない。確認済みの「例外を送出しない」から、内部でも例外が発生しないことやログ・画面通知がないことを導かない。

情報不足は必要な箇所だけで扱う。不要な理由を足さずに書けるなら完成させる。曖昧さを保って書けるなら保ち、完成に不可欠な情報が欠ける箇所だけ保留する。独立して書ける部分を進め、最小限の確認事項を完成稿と分けて示す。別の文章作成の一部を担当するときは、その担当側へ不足を返す。未確定箇所を黙って完成済みに見せない。

URL、パス、コード、コマンド、設定、識別子、正式名称、引用、検索に必要な原語、リンク先、Markdown 構文を特定し、依頼された場合を除き保護する。同じ語形でも一般的な説明語まで一律に保護しない。定着した専門用語や自然な比喩は、AI の出力に多いというだけで削らない。一般語の日本語化、原語の維持・併記、文全体の組み直しを文脈で選び、助詞、語の組合せ、修飾・否定、主語、敬語と発話意図まで確認する。一般的な説明だけに使う英語は、同じ文に正式名称や識別子があっても一括して残さない。

- `deterministic`、「契約」「ゲート」「門」「静かに壊れる」「静かに失敗する」「黙って無視される」「地味に効く」「効いてくる」「正本」、または一般説明の storage state と API 名 `storageState`、UI 表示 “Storage State” のように説明語・識別子・表示名が並ぶ箇所では、[`references/wording-decisions.md`](references/wording-decisions.md) の該当箇所を読む。
- 他言語から日本語へ翻訳する場合、対象全体の語彙傾向を見直す場合、または判断する表現の種類が特定できない場合は、同 reference を最初から最後まで読む。原語と日本語を一対一の固定置換にしない。

表現だけを直す依頼では、節構造やリスト・表の役割を保つ。全体の再構成を任された場合は見出しや順序も変えられるが、条件の適用先、手順の依存、アンカーと参照リンクの対応を守る。必要な構成や説明までこの Skill で整え、別の Skill を完成の必須条件にしない。

## 完成稿を全文確認する

完成稿そのものを最初から最後まで読者の立場で読み直す。入力と照合し、主張、条件、否定、確度、帰属、発話意図、対象範囲、保護対象、段落・リンク・Markdown の意味が変わらず、必要な説明があり、読者に不要な作業経緯や開示不適切な情報が混じらないことを確かめる。新たな英語混在、用語の揺れ、抽象語の集中も見る。関連文書が同じ依頼にある場合だけ文書間の整合を確かめる。変更後の方が不正確、冗長、または文体に合わないなら元の表現を維持する。

求められた形式と範囲で完成稿を返す。語彙判断や修正理由は求められた場合だけ、完成稿と分けて示す。

## 対象外

- 通常のコーディング、調査、質疑応答の途中で日本語を返すだけの作業
- 表記統一、誤字、句読点だけを直す機械的な校正
- 文章を完成させず、構成案、見出し、論証、情報設計だけを扱う編集
- AI が生成した文章かどうかの判定
- 禁止語表や固定した置換規則の作成と適用
