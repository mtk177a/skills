# 自然な日本語を書く

日本語の文章が主要な成果物なら、新規執筆、翻訳、リライト、推敲を依頼の範囲で完成させる。読者が内容と文同士の関係を理解できるよう、必要な構成、短い説明、語彙、構文を整える。

この Skill だけで任された完成稿まで仕上げる。別の Skill の併用を必須条件にせず、AI らしさの検出や禁止語の置換も目的にしない。

## 依頼と入力を読む

### 読者と利用文脈

依頼と参照できる文脈から、目的、読者、媒体、読後に理解・判断・操作してほしいことを捉える。

ユーザーの明示指定、引用、対象文書の規約、既存の文体・用語を優先する。

読者が通常参照する返信先のメール、既存スレッド、直前の節は文脈として使える。読者に見えない執筆用の会話だけに依存する指示語は、完成稿に残さない。

### 入力の役割と変更幅

入力を見た目で原稿かメモかに決めず、何を忠実に保ち、何を執筆材料として選べるかを判断する。

要約・削除・再構成まで任されているかを確認する。指定がなければ「読者には不要そう」という理由だけで原稿の主張を削らない。

毎回の確認を入口条件にせず、変更幅が不明で意味が変わる箇所だけを確認する。

### 忠実な翻訳・推敲

- **意味保持**：主張、主体と対象、条件、否定・修飾の範囲、確度、帰属、依頼・許可・義務などの発話意図を守る。
- **表現の調整**として、語順、文の分割、主語の明示・省略、丁寧さは変えられる。
- **翻訳の事実確認**は別の判断とする。原文の全事実を独立に調査する依頼ではないため、未検証というだけで止めたり主張を直したりしない。
- **原文の曖昧さ**は訳文でも保てるなら保ち、不可欠な選択だけを確認する。
- **原文の誤りの疑い**を示すなら、訳文と分ける。

### 材料からの新規執筆・任された要約や再構成

- **情報選択**では、読者に必要な情報を選ぶ。執筆指示、訂正の経緯、内部作業名は、読者に必要な内容でなければ持ち込まない。
- **情報を選ぶ権限**があっても、指定された全項目は伝え、要約しても結論を支える条件や留保は残す。
- **掲載の可否**は必要性と分けて判断する。読者に必要でも開示できない情報は、言い換えるだけで掲載可能にはならない。

## 内容を確定する

### 根拠に沿って補う

入力が支える関係の明示、情報の並べ替え、短い語義説明を行い、依頼された読者が使える文章にする。

一般的な語義と製品・案件固有の仕様を分け、新しい事実、原因、判断理由、要件、約束、期限を作らない。確認された挙動から、別の挙動の有無を推測しない。具体例は参照資料の[「静かに壊れる、静かに失敗する」](references/wording-decisions.md#静かに壊れる静かに失敗する)に置く。

### 不足を局所的に扱う

不要な理由を足さずに書けるなら完成させる。曖昧さを保って書けるなら保ち、完成に不可欠な情報が欠ける箇所だけ保留する。

独立して書ける部分を進め、最小限の確認事項を完成稿と分けて示す。未確定箇所を黙って完成済みに見せない。

別の文章作成の一部を担当するときは、その担当側へ不足を返す。

## 文章として仕上げる

### 保護対象と編集許可を見分ける

URL、パス、コード、コマンド、設定、識別子、正式名称、引用、検索に必要な原語、リンク先を特定し、依頼された場合を除き保護する。同じ語形でも一般的な説明語まで一律に保護しない。

保護対象を変更する明示の依頼がある場合は、その対象と範囲に限る。

### 語彙を選ぶ

定着した専門用語や自然な比喩は、AI の出力に多いというだけで削らない。一般語の日本語化、原語の維持・併記を文脈で選ぶ。

一般的な説明だけに使う英語は、同じ文に正式名称や識別子があっても一括して残さない。

### 文を組み立てる

単語だけを置き換えず、文全体の組み直しも選ぶ。助詞、語の組合せ、修飾・否定の範囲、主語、敬語と発話意図を整える。

### 構造と Markdown を守る

表現だけを直す依頼では、節構造やリスト・表の役割を保つ。全体の再構成を任された場合は見出しや順序も変えられるが、条件の適用先と手順の依存を守る。

コードスパン、コードブロック、見出し、リスト、表、引用などの Markdown 構文は、文章を自然にする目的だけでは変更しない。リンクの表示文字列を整える場合も、リンク先、アンカー、参照リンクとの対応を保つ。

### 判断例を必要な範囲で読む

`deterministic`、「契約」「ゲート」「門」「静かに壊れる」「静かに失敗する」「黙って無視される」「地味に効く」「効いてくる」「正本」を扱う場合は、[表現別の判断例](references/wording-decisions.md#表現別の判断例)の該当項目を読む。

一般説明の storage state、API 名 `storageState`、UI 表示 “Storage State” のように役割が並ぶ箇所では、[説明語・識別子・表示名](references/wording-decisions.md#説明語識別子表示名)を読む。

他言語から日本語へ翻訳する場合、対象全体の語彙傾向を見直す場合、または判断する表現の種類が特定できない場合は、[参照資料](references/wording-decisions.md)を最初から最後まで読む。原語と日本語を一対一の固定置換にしない。

## 完成稿を全文確認して返す

完成稿そのものを最初から最後まで読者の立場で読み直す。

- **意味**：入力と照合し、主張、条件、否定、確度、帰属、発話意図、対象範囲と保護対象が変わっていないか確かめる。
- **完成度**：読者に必要な説明があるか確かめる。
- **開示**：材料から選んで書いた場合は、不要な作業経緯や開示不適切な情報が混じらないか見る。
- **表現**：新たな英語混在、用語の揺れ、抽象語の集中を確認する。
- **形式**：段落・リンク・Markdown の意味を確認する。
- **文書範囲**：複数の関連文書が同じ依頼に含まれる場合だけ、共有する意味と用語の整合を確かめる。同じ依頼に含まれない文書へ作業を広げない。

変更後の方が不正確、冗長、または文体に合わないなら元の表現を維持する。

求められた形式と範囲で完成稿を返す。語彙判断や修正理由は求められた場合だけ、完成稿と分けて示す。

## 対象外

- 通常のコーディング、調査、質疑応答の途中で日本語を返すだけの作業
- 表記統一、誤字、句読点だけを直す機械的な校正
- 文章を完成させず、構成案、見出し、論証、情報設計だけを扱う編集
- AI が生成した文章かどうかの判定
- 禁止語表や固定した置換規則の作成と適用
