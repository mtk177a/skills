# 書く内容を構造化する

## 目的

必要な情報を選び、論理構造を設計し、読者と目的に合う形で表現することで、文章を作成・改善する。

段落、リスト、表、見出し、節、ファイルの境界は、あらかじめ決まった入れ物ではなく、情報を表現するための手段として扱う。

一つの文から関連するファイル群まで、情報に応じた範囲で作業する。\
書式を増やすこと、文章を短くすること、ファイルを増やすことを、そのまま構造の改善とみなさない。

## 作業手順

### 1. 目的と範囲を把握する

- 想定読者、その読者が行う作業、文章を掲載する媒体、文章によって実現したい結果を特定する。
- 依頼が新規作成、改稿、再構成、レビュー、変更の要否の判断のいずれを求めているか確認する。
- 適用される規約、既存の内容、必要な情報、変更が許可された範囲を確認する。
- 情報の文脈を理解するために必要なら、前後の節や関連資料を確認する。\
  既存の段落、節、ファイルの境界が正しいとは仮定しない。
- 最終的な読者が参照できる情報と、執筆時にしか参照できない文脈を区別する。

### 2. 根拠を確認し、情報を選ぶ

- 読者が理解、判断、行動するために必要な情報を特定する。
- 確認済みの事実、権限のある主体が決定した事項、仮定、解釈、未確認事項を区別する。
- 重要な事実の主張には、適切な一次情報を使う。\
  不足している事実、決定事項、要件、判断理由を作り出さない。
- 提供された内容を忠実に編集する作業と、掲載する情報を選べる執筆作業を区別する。
- 既存の内容を再構成するときは、必要な主張、条件、不確実性、約束、許可、安全上の制約を保つ。
- 運用上の指示を改稿する前に、提供された入力、必要な出力、対象の選択規則、許可、禁止、失敗時の対応を、参照元と対応する作業メモに整理する。\
  未定義の挙動は未定義として扱う。\
  保守者の作業と、実行する読者に必要な安全上の制約を区別する。
- 表現形式の選択と運用上の要件を区別する。\
  改稿で処理順、対象の選択、必須・任意の行動、停止・継続条件、アクセス範囲、必須の出力制約を変えるには、その根拠か、その挙動を設計する明示的な権限が必要である。\
  読みやすくする許可だけでは、その権限は得られない。
- 成果物を単独で使えるようにするときは、読者に必要な既存の指示を残し、不足する運用ルールを作り足さない。\
  未定義の挙動は未定義のまま保ち、重要な不足は完成稿と分けて示す。\
  依頼された作業を完了できない場合だけ確認する。
- 掲載する情報を選べる場合は、無関係な調査経緯、重複した説明、根拠のない結論、読者の作業に役立たない詳細を除く。
- 同じ情報を複数の成果物で管理している場合は、正式な管理元となる場所を特定する。

### 3. 情報を分析・整理する

表現形式を選ぶ前に、意味のある情報の単位を特定する。

- 各単位の主題、目的、情報の種類を判断する。\
  情報の種類には、定義、事実、属性、条件、規則、手順、制約、具体例などがある。
- 同等、対比、所属、包含、順序、依存、因果など、情報の単位どうしの関係を特定する。
- 単に近くに書かれていることや、都合のよいリストの長さではなく、一貫した意味のある基準で情報をまとめる。
- 読者が一緒に参照する必要のある定義、条件、例外、具体例は、関連が分かるようにまとめて配置する。
- 元の段落や節が同じでも、主題や目的の異なる情報は分ける。
- 関連する情報を孤立した記述へ細分化せず、意味のあるつながりを保つ。

文、段落、箇条書きの項目、表、見出し、ファイルの境界が、その中にある情報自体の境界を決めるわけではない。

### 4. 構造と配置を設計する

最終的な文章を書く前に、情報をどう構成するか決める。

- 情報の単位ごとに、適切な詳しさとまとめ方を選ぶ。
- 並列する項目は、主題、役割、抽象度を揃え、比較できるようにする。
- 親子関係、順序、依存関係、例外を、適切な階層で表す。
- 各見出しが、その下にある内容と対象範囲を正確に表しているか確認する。
- 散在する記述から読者が関係を組み立て直さなくても、関連情報を見つけられるように構成する。
- 節やファイルをそのまま維持するか、分割するか、統合するか、内容を移動するか検討する。
- 複数の成果物を扱う場合は、それぞれの目的、情報の正式な管理元、必要な情報へのたどり方、保守責任を考慮する。
- 単独で機能する必要のある成果物には、一部が重複しても、必要な情報を残す。
- 理解、利用、保守のしやすさが改善しないなら、階層、ファイル、相互参照を増やさない。

構造上の問題は、適切な範囲で評価する。\
一つの段落に見える問題でも、節、文書、文書群の再構成が必要な場合がある。

より広い範囲の構造を調べても、依頼された範囲を超える変更が許可されるわけではない。\
範囲外の変更は、承認なしに実行せず、提案として示す。

### 5. 表現形式を選び、執筆する

情報の意味、関係、利用目的に応じて、表現形式を選ぶ。

- 文章: 一貫した主題、論拠、文脈、因果関係を説明する。
- 箇条書き: 実行順序を持たない、区別できる並列項目を示す。
- 番号付きリスト: 順序のある手順や流れを示す。\
  適切な場合は、各手順の詳細や確認事項を、その手順の下に配置する。
- 入れ子のリスト: 見た目のための字下げではなく、実際の包含関係や親子関係を表す。
- 表: 繰り返し現れる属性、定義、条件、比較を、明確にした観点に沿って示す。
- コードブロック: 正確な構文、設定、コマンド、出力形式など、文字どおりに扱う構造を示す。
- 図: 文章では効率よく伝えにくい関係、流れ、構造を明確にする。

これらの形式は、状況に応じて判断して使う。

- 無関係な主題を、一つの箇条書きの項目、段落、表、節にまとめない。
- 各項目や文を短くすることだけを目的に、関連する情報を分断しない。
- 一緒に示すことに意味がないなら、独立した主題を一つの表にまとめない。
- より明確な構造で示せるのに、長い列挙、独立した条件、実行すべき項目を密度の高い文章に埋め込まない。
- 具体例と例外は、それらが説明する定義や規則の近くに置く。
- 見出しなどの構造要素は、それによる区別が読者に役立つ場合にだけ使う。
- 自然な言葉遣い、意味のある文のつながり、十分な説明を保つ。

対象媒体の慣習に従い、短いメッセージに長い文書向けの構造を押し付けない。

### 6. 結果を検証する

執筆時の会話を参照できない読者の立場で、結果を見直す。

次を確認する。

- 内容が想定読者と目的に合っている。
- 必要な情報が揃い、参照元に照らして正確で、必要な条件や留保が付いている。
- 各節、段落、箇条書きの項目、表の役割を読み取れる。
- 分類基準、階層、順序、配置が、情報の実際の関係を表している。
- 見出しが内容を正確に表し、対象範囲を誤解させない。
- 関連する情報を一緒に見つけ、理解できる。
- 表現形式によって、情報を見つけ、比較し、理解し、利用しやすくなっている。
- 構造が不必要に細分化、重複、複雑化していない。
- 再構成によって、既存の意味、要件、制限、権限のある主体が決定した事項が失われていない。
- 運用上の指示の改稿では、原文と結果を双方向に照合する。\
  既存の要件を実行する読者が引き続き参照でき、新たな必須の指示は提供された要件と同じ意味か、許可された設計作業で裏付けられている。\
  根拠のない要件は仮定で補完せず削除し、必要な設計提案は完成した成果物と分ける。
- 複数ファイルへの変更で、必要なリンク、参照、単独で機能するための条件が保たれている。

該当する場合は、事実の主張、リンク、具体例、コマンド、生成された内容、リポジトリ固有のチェックを、実際の参照元や実行結果に照らして検証する。

構造上の問題が残る場合は、見た目だけを整えるのではなく、情報の分析と、より上位の構成を見直す。

## 出力と作業上の制約

- 新規作成や許可された改稿では、書き方の説明ではなく、依頼された完成稿を作る。
- レビューのみの依頼では、対象を変更せず、構造上の問題とその影響を説明し、改善案を示す。
- 変更が不要なら、改善を無理に作り出さず、既存の内容を保つ。
- 必要な情報や権限が不足している場合は、具体的な不明点を示し、独立して進められる作業は可能な範囲で完成させる。
- 執筆メモ、却下した案、内部の修正履歴は、読者に役立つ場合を除いて完成稿に含めない。
- Skill の起動を、ファイルの編集、公開、他者への連絡、許可範囲の拡大の承認とみなさない。
- 完了した変更、実際に行った確認、未解決事項、提案する範囲外の変更を簡潔に報告する。
