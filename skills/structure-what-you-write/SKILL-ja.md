# 書く内容を構造化する

関係のある情報を選び、その論理構造を設計し、読者と目的に合う形で表す。\
段落、リスト、表、見出し、節、ファイルは、情報を表すための手段であり、決まった入れ物ではない。\
一つの文から、関連するファイルの集まりまで、情報が必要とする範囲で作業する。\
より良い構造が、より少ない書式、より長い文章、より少ないファイルを意味することもある。

## 作業手順

### 1. 目的と範囲を定める

- 読者、読者の作業、媒体、内容が支えるべき結果を特定する。
- 依頼の種類を特定する: 作成、改稿、再構成、レビュー、変更が必要かどうかの判断。
- 適用される慣例、既存の内容、必要な情報、許可された変更の範囲を特定する。
- 文脈を理解するのに必要な場合は、周囲の節や関連する資料を読む。\
  既存の段落、節、ファイルの境界も、作業の対象として評価する。
- 最終的な読者が持つ情報と、執筆中にだけ存在する文脈を分ける。

### 2. 証拠を確かめ、情報を選ぶ

- 読者が理解し、判断し、行動するのに必要な情報を特定する。
- 確立した事実、許可された判断、前提、解釈、不明点を分ける。
- 重要な事実の主張には、適切な一次情報を使う。\
  書くのは、情報源が裏付ける事実、判断、要件、理由だけにする。
- 改稿では、構造と言い回しだけでなく、読者の判断に影響する既存の主張も確かめる。
- コードやその他の実装の証拠が示すのは、現在の挙動だけである。\
  要件、設計の理由、方針、担当、許容できるリスクには、別の証拠が必要である。
- 示された内容を忠実に編集することと、内容を選べる執筆とを分ける。
- 既存の内容を再構成する場合は、その必須の主張、条件、不確かさ、約束、許可、安全上の制約を保つ。
- 運用の指示を改稿する前に、その構成要素を、出典とともに作業メモとして記録する。\
  構成要素とは、入力、出力、選択の規則、許可、禁止、失敗時の扱いである。\
  情報源が定めていない挙動は、未定義と記す。\
  保守者の責務と、実行する読者が引き続き必要とする安全策を分ける。
- 表し方の選択と、運用上の要件を分ける。\
  改稿の中には、挙動を変える変更がある: 処理の順序、項目の選択、必須または任意の行動、停止と継続の条件、アクセスの範囲、必須の出力の制約。\
  これらの変更は、裏付ける証拠か、その挙動を設計する明示的な権限がある場合だけ行う。\
  読みやすくする許可は、その権限を与えない。
- 成果物は、読者が必要とする、示された指示によって単独で読めるものにする。\
  定められていない挙動は、未定義のままにする。\
  重要な不足は、完成した文章とは別に報告し、依頼された作業を妨げる場合だけ尋ねる。
- 内容を選べる場合は、関係のない調査の経緯、繰り返しの説明、裏付けのない結論を省く。\
  読者の作業に必要のない詳細も省く。
- 複数の成果物が同じ情報を含む場合は、その情報の基準となる場所を特定する。

### 3. 情報を分析し、整理する

表し方を選ぶ前に、情報の単位を特定する。

- 各単位の主題、目的、種類を特定する。\
  種類には、定義、事実、属性、条件、規則、手順、制約、例がある。
- 単位どうしの関係を特定する。\
  たとえば、同等、対比、所属、包含、順序、依存、原因である。
- 情報は、一つの一貫した、意味のある基準でまとめる。
- まとめ方は、読者が行う判断から選ぶ。\
  一つの項目が複数の選択肢に当てはまる場合は、選択肢ごとに整理し、その項目を当てはまる各選択肢の下に挙げる。
- 読者が一緒に必要とする定義、条件、例外、例は、一緒に置く。
- 異なる主題や目的に役立つ情報は、元の文章で同じ段落や節にあっても分ける。
- 関係のある情報どうしのつながりを保つ。

情報そのものの境界は、文、段落、箇条書き、表、見出し、ファイルの境界と異なることがある。

### 4. 構造と配置を設計する

最終的な形を書く前に、情報をどう整理するかを決める。

- 情報の単位ごとに、詳しさの程度とまとめ方を選ぶ。
- 並列する項目は、主題、役割、抽象度をそろえて比べられるようにする。
- 親子関係、順序、依存、例外は、適切な階層で示す。
- 各見出しが、その下の内容と範囲を表すようにする。
- 兄弟の見出しには、同じ種類の内容と、親に対する同じ関係を持たせる。\
  手順と参照資料が一つの文書にある場合は、それぞれのまとまりを、それぞれの親見出しの下に置く。\
  関係をすでに示している既存の見出しがあれば、それでよい。
- 一つの手順だけが使う詳細は、その手順の中に置く。
- 兄弟の見出しは、手順なら動作、参照資料なら名詞のように、同じ形で書く。
- 各文書は、一つの主な読者に向けて書く。\
  読者が推測できない場合は、文書の冒頭でその読者を示す。\
  AI エージェントに向けた制約は、人向けのガイドではなく、エージェント向けの指示にだけ置く。
- 読者が関係のある内容を一か所で見つけられるように、情報を整理する。
- 各節やファイルを、そのまま残すか、分けるか、統合するか、内容を移すかを決める。
- 複数の成果物が関わる場合は、それぞれの目的、基準となる場所、案内、保守を考える。
- 単独で機能する成果物が必要とする情報は、重複が生じても保つ。
- 階層は、包含を示すために使う。\
  異なる種類の内容が必要とする場合は、階層を深くする。\
  ファイルや相互参照を加えるのは、理解、利用、保守が良くなる場合だけにする。

構造の問題は、適切な階層で評価する。\
一つの段落に見える問題が、節、文書、文書の集まりの再編を必要とすることもある。\
変更するのは依頼された範囲だけにし、範囲の外の変更は提案する。

### 5. 表し方を選んで書く

各表し方は、情報の意味、関係、使われ方から選ぶ。

- **文章**: 一つの主題、推論、文脈、原因を説明する。
- **箇条書き**: 実行の順序を持たない、別々の並列する項目を示す。
- **番号付きリスト**: 順序のある手順を示す。\
  手順に短い詳細がある場合は、手順に太字の名前を付け、詳細をその下に箇条書きで置く。\
  手順が複数の段落やコードブロックを含む場合は、各手順にそれぞれの見出しを付ける。
- **入れ子のリスト**: 実際の包含や親子関係を示す。
- **表**: 明確な軸にわたって、繰り返される属性、定義、条件、比較を示す。\
  セルに複数の文や独立した条件が必要な場合は、見出しかリストを使う。
- **コードブロック**: 正確な構文、設定、コマンド、出力の形式、その他の文字どおりの構造を示す。
- **図**: 文章では効率よく示しにくい関係、流れ、構造を示す。

これらの選択は、判断して当てはめる。

- 各箇条書き、段落、表、節には、一つの主題を持たせる。
- 箇条書きや文が長くなっても、関係のある情報は一緒にする。
- 独立した主題を一つの表にまとめるのは、まとめた見方に明確な用途がある場合だけにする。
- 長い列挙、独立した条件、行動は、詰まった文章の中ではなく、明確な構造で示す。
- 例と例外は、それが説明する定義や規則の近くに置く。
- 各節は、その要点から始める: その節で読者が何をでき、何を知るか。\
  条件や限界は、その要点の後で、それが影響する手順や項目の中に置く。\
  行動の前に警告を置くのは、読者がその行動の前に知る必要がある場合だけにする。
- 原因、対比、条件のような文どうしの論理的な関係は、明示的なつなぎの言葉で示す。
- 主体が、読者、ほかの人、エージェント、システムの間で変わるたびに、その主体を示す。\
  どの読者にとっても同じ意味になる呼び方を使う。\
  たとえば、人とエージェントの両方が読む文書では、「ユーザー」が別々の人を指すことがある。
- 一つの指示対象には一つの用語を使う。\
  用語の普通の意味が、実際に起こることと合っているかを確かめる。
- 見出しやその他の構造の要素は、その区別が読者の役に立つ場合に使う。
- 自然な言葉、意味のある話の移り、十分な説明を保つ。

対象の媒体の慣例に従う。\
短いメッセージには、短いメッセージの構造を使う。

### 6. 結果を確かめる

執筆中の会話を見ていない読者として結果を読み、次の項目を確かめる。

- 内容が、意図した読者と目的に役立っている。

- 必要な情報があり、情報源に対して正しく、適切に限定されている。

- 各節、段落、リストの項目、表に、はっきりした役割がある。

- まとめ方の基準、階層、順序、配置が、情報の実際の関係に合っている。

- 各見出しがその内容を表し、誤った範囲を示していない。

- 見出しだけを読んでも、各節の話題が分かる。

- 各節の最初の文が、その要点を示している。

- 複数の節や文書を一緒に変えた場合は、各節がこの一覧の基準を満たしている。\
  構造を直しただけでは、改稿は完了しない。

- 読者が、関係のある情報を一緒に見つけて理解できる。

- 各表し方が、情報を見つけ、比べ、理解し、使うのを容易にしている。

- 構造は、余計な断片や繰り返しがなく、情報が許す範囲で単純である。

- 再構成した内容が、意味、要件、限界、許可された判断を保っている。

- 運用の改稿では、元の文章と結果を両方向に比べる。

  - 既存の各要件が、実行する読者にとって引き続き利用できる。
  - 新しい必須の指示がそれぞれ、示された要件と同じであるか、許可された設計の作業に支えられている。

  裏付けのない要件は取り除く。\
  必要な設計の提案は、完成した成果物の外に置く。

- 複数のファイルの変更が、必要なリンク、参照、単独での働きを保っている。

当てはまる場合は、事実の主張、リンク、例、コマンド、生成した内容、リポジトリの確認を確かめる。\
その情報源と、実行した結果に照らして確かめる。\
構造の問題が残る場合は、情報の分析と、より上の階層の整理を見直す。

## 出力

- 作成や許可された改稿では、書き方の説明ではなく、完成した内容を出す。

- レビューだけの依頼では、構造の問題を特定し、その影響を説明し、改善を提案する。\
  対象は変更しない。

- リポジトリの文書に変更が必要かを評価する場合は、次のいずれか一つの結果を示す。

  - 更新が必要
  - 文書への影響なし（理由とともに）
  - 不明点のため判断できない（足りない証拠や判断とともに）

- 変更が必要ない場合は、既存の内容を保つ。

- 必要な情報や権限が欠けている場合は、具体的な不確かな点を示し、独立して進められる作業を完成させる。

- 執筆のメモ、退けた代案、内部の改稿の経緯は、読者の役に立つ場合を除き、完成した内容に入れない。

- ファイルの編集、資料の公開、ほかの人への連絡は、許可された範囲の中でだけ行う。

- 完了した変更、実行した確認、未解決の問題、範囲の外の変更の提案を報告する。\
  構造の変更と文の変更を分け、節によって改稿の深さが違う場合はそれを示す。
