# 読み手に伝わる説明を書く

依頼された説明を、指定された言語と形式で完成させる。想定する読み手は依頼者本人でも、依頼者が文章を届ける相手でもよい。単語を簡単にしたり文を短くしたりするだけでなく、答えとそれを支える情報の関係を読み手が追えるようにする。既存文の修正では、根拠のある元の意味と依頼された編集範囲を守る。

## 説明を組み立てる

1. 読者が実際に知りたいことと、説明の目的を捉える。読後に何を理解、比較、判断できればよいかを考える。依頼に示された読者と文脈を使う。指定がなければ妥当な前提を置いて書き始め、欠けた選択によって答えが大きく変わるときだけ確認する。
2. 問いに答えるために必要な情報を選ぶ。利用できる根拠、提供資料の範囲、不可欠な前提、適用条件、不明点、開示できる範囲を確かめる。読者が分野に詳しくても、今回の案件に固有の前提まで共有しているとは限らない。必要なつながりを補い、無関係な基礎講座は加えない。不足を埋めるために事実、原因、方針、確度を作らない。結論を左右する事実が得られなければ、説明できる部分を示したうえで限界を明記する。完成に不可欠な場合は、その事実を確認する。
3. 読者が追うべき関係を整理する。必要に応じて、原因と結果、条件と結果、比較、順序、全体と部分を明確にする。個別の例と、それが示す一般原則を区別する。歴史や複雑な現象では、根拠に応じて複数の要因を残し、確認された事実、解釈、仮説を分ける。
4. この問いに合う順序と形式を選ぶ。答え、背景、仕組み、根拠、留保を、それぞれ必要になる箇所に置く。情報の関係と読者の目的に応じて、段落、箇条書き、手順、表を使う。前提から結論までのつながりを示し、事実を列挙するだけで推論が伝わると考えない。具体例が原則や違いの理解に役立つなら使い、その例が当てはまる範囲を示す。結論から始めること、長さ、例の数、定型文を一律に強制しない。
5. 完成稿を読者の立場で読み直す。問いへの答え、理由、重要な適用条件、不確実性、開示の適切さを確かめる。執筆中の経緯、根拠のない追加、読者の助けにならない詳細を除く。必要な留保は、文章が長くなっても残す。

元の文章がある場合は、忠実に保つべき本文と、選択・再構成を任された材料を区別する。重要な主張、主体、条件、否定、確度、正確に保つべき文字列を守る。これらが「分かりやすくする」という意図と衝突するなら、黙って主張を変えず、その点を明示する。

## 出力と具体例

依頼された形式で、完成した説明または修正文を返す。分析用のワークシートを毎回見せたり、読者に小テストを出したり、次の行動を付け足したりしない。根拠の不足が読者の結論に影響するときだけ、その点を添える。

必要な前提の選び方、例と原則の分け方、難しい説明の順序を考えるときは、[説明の具体例](references/explanation-examples.md) を読む。具体例は判断の参考であり、すべての回答に同じ文言や構成を当てはめるためのものではない。
